# 말판 원정대 (웹 시제품 v0.6 · PWA)

동물 원정대가 도깨비에게 빼앗긴 윷판·주사위판·체스판을 되찾는 점수 쌓기 로그라이크. (이전 가제 「윷판을 뒤집어라」)

기획은 [DESIGN.md](DESIGN.md).

```bash
cd yut
python tools/save-server.py . 7373   # 캐시 없는 개발 서버 → http://localhost:7373
npm test                       # 규칙 테스트 (node --test)
npm run sim -- 2000            # 밸런스 시뮬레이터: 정책별 라운드 통과율·클리어율
```

- 메인에서 **원정 떠나기**(윷놀이판 → 주사위판 → 체스판, 6라운드) 또는 **판 하나만**(그 판 2라운드, 목표가 낮다)을 고른다
- 주소에 `?seed=5` 를 붙이면 같은 판이 다시 나온다. `?round=3` 은 3라운드(주사위판), `?round=5` 는 체스판부터 시작(테스트용)
- 화면: 폰(세로)은 390×844 틀, PC(가로가 긴 창)는 판이 왼쪽을 가득 채우고 점수·굴림·버튼이 오른쪽 패널로 간다
- 키보드: Space/Enter 굴리기 · R 다시 굴리기
- 판: 윷놀이판(윷) → 주사위판(40칸, 주사위 2개, 모두의 마블식 칸 이벤트) → 체스판(8×10, 기물 주사위). 비스듬히 내려다보는 입체 시점, 카메라가 따라다니고 끌어서 둘러볼 수 있다
- 원정대: 호랑이(맹공)·토끼(꾀 많은 도망)·앵무새(반가운 소식)·판다(든든한 등). 판 위 내 말을 누르면 능력이 보인다. 걷기·환호·좌절·춤 동작이 있다
- 스킬: 캐릭터마다 눌러 쓰는 기술 하나(포효·깡충·수다·대나무 방패). 라운드에 한 번, 판 위에 나와 있을 때 던지기 전에. 쓰면 컷인 연출이 나온다
- 굴림 도구: 윷가락·주사위·기물 주사위를 three.js 로 입체로 그려 판 위로 던진다. 그림체는 판·캐릭터와 같게(같은 팔레트·조명, 윤곽 먹선, 납작한 타원 그림자). 따로 굴림 칸은 없고, 결과 도장은 판 오른쪽 위에 찍힌다. three.js 를 못 불러오면 2D 그림이 판 가운데에 잠깐 뜬다
- 캐릭터 도감: 메인의 "캐릭터 도감" 단추나 원정대 카드를 누르면 연다. 캐릭터별 동작 보기(대기·걷기·환호·좌절·춤), 능력·스킬 설명, 스킬 연출 미리 보기, 도깨비와 도깨비 대장 규칙
- 돌발 사건: 라운드마다 2번, 위쪽 예고("사건 3번 뒤")에 맞춰 판 전체에 일이 터진다 — 보따리 소나기·황금 칸·회오리바람·신명 굿판·순풍·도깨비 장날(좋은 일), 도깨비 잔치(나쁜 일)

## 앱(PWA)으로 설치

**바로 하기: https://alekf9099.github.io/malpan/** (공개 저장소 [alekf9099/malpan](https://github.com/alekf9099/malpan) 의 GitHub Pages)

`manifest.webmanifest` · `sw.js` · `assets/icons/` 가 들어 있어 HTTPS 주소에 올리면 홈 화면에 설치할 수 있다.

배포 갱신 — 작업 저장소의 `yut/` 폴더만 떼어 공개 저장소로 보낸다(몇 분 뒤 Pages 에 반영):

```bash
git subtree split --prefix=yut -b malpan-pages
git push https://github.com/alekf9099/malpan.git malpan-pages:main
git branch -D malpan-pages
```

새 버전을 올릴 때 `sw.js` 의 `CACHE` 이름(예: `malpan-v7` → `malpan-v8`)을 바꾸면 설치된 앱의 옛 캐시가 지워진다.

- 안드로이드 크롬: 메뉴 → **앱 설치**(또는 홈 화면에 추가)
- 아이폰 사파리: 공유 → **홈 화면에 추가**
- PC 크롬·엣지: 주소창 오른쪽 설치 아이콘

한 번 끝까지 열어 두면 오프라인에서도 열린다(네트워크 우선, 끊기면 캐시). 개발 서버(localhost)에서는 캐시가 수정 확인을 방해하지 않도록 서비스 워커를 등록하지 않는다. 아이콘은 `python tools/make-icons.py` 로 다시 만든다.

## 구조

| 경로 | 내용 |
|---|---|
| `src/core/` | 규칙 전부. DOM 을 모르고 이벤트 목록을 돌려준다 — `board` 29칸 그래프 · `sticks` 던지기 확률 · `round` 업기·잡기·점수·도깨비 AI · `run` 라운드·상점·보스 · `items` 부적·칸·윷가락 |
| `src/core/heroes.js` | 원정대 캐릭터와 고유 능력(훅)·스킬(`active`). 스킬 효과는 `round.js` 의 `useSkill` |
| `src/core/events.js` | 돌발 사건 목록과 라운드별 계획(언제·무엇) |
| `src/core/boards/` | 판 3종(`yut`·`marble`·`chess`). 공통 인터페이스: `roll` 굴리기 · `options` 둘 수 있는 수 · `tile` 칸 이벤트 · `rollsFor` 결과 확률(위험도 계산용) |
| `src/ui/` | 그리기만. `board-view` 아이소메트릭 판 · `camera` 따라가기·맞추기·끌기 · `roller` 윷가락·주사위·기물 주사위 · `anim` 점프·찌그러짐·날려 보내기 · `fx` 먼지·폭죽·스티커 · `art` 캐릭터 스프라이트·부적·칸 그림 · `sound` Web Audio 합성 · `app` 이벤트를 차례로 연출 |
| `tests/` | 판 경로, 확률, 업기·잡기·골인, 점수 공식, 부적 순서, 보스, 엽전, 시드 재현, 1000판 종료 보장 |
| `tools/sim.mjs` | 무작위 · 탐욕 · 상점까지 쓰는 정책으로 N 런을 돌린다. 네 번째 인자로 판 하나만(`yut`·`marble`·`chess`) |

## 현재 밸런스 (v0.6, 2000런, 돌발 사건·스킬 포함)

시뮬레이터의 정책은 random 외에는 스킬도 쓴다(쓸 수 있으면 바로, 판다 방패는 위험한 말이 있을 때만).

전체 원정 — 목표 400·700 / 1200·1600 / 1650·1950

| 정책 | R1 윷 | R2 윷 보스 | R3 주사위 | R4 주사위 보스 | R5 체스 | R6 체스 보스 | 클리어 |
|---|---|---|---|---|---|---|---|
| 무작위 | 71.7% | 35.7% | 41.8% | 18.7% | 0% | — | 0% |
| 탐욕(상점 안 씀) | 94.4% | 74.8% | 90.7% | 60.8% | 24.8% | 9.3% | 0.9% |
| 탐욕 + 상점 | 94.4% | 81.3% | 96.6% | 81.3% | 60.1% | 41.7% | 15.1% |
| 위험 고려 + 상점 | 96.8% | 83.8% | 95.9% | 82.5% | 68.0% | 45.3% | 19.8% |

판 하나만 — 부적 없이 시작하므로 목표를 낮췄다

| 판 (목표) | 탐욕 + 상점: 1라운드 | 보스 | 클리어 |
|---|---|---|---|
| 윷놀이판 (400 · 700) | 94.4% | 81.3% | 76.7% |
| 주사위판 (1000 · 1450) | 95.0% | 75.2% | 71.4% |
| 체스판 (360 · 600) | 72.3% | 56.5% | 40.9% |

스킬이 들어가 전체 원정 클리어율이 13.6% → 19.4% 로 오르자 목표를 올려 15.1% 로 맞췄다(주사위판이 가장 많이 쉬워졌다). 체스판은 점수가 들쭉날쭉해(나이트·퀸이 나오느냐) 혼자 하는 판 중 가장 어렵다.

판마다 점수가 나오는 속도가 달라 목표를 판별로 맞췄다(주사위판이 가장 점수가 크다). 체스판은 상점 없이는 거의 못 넘는다 — 부적을 모으지 않으면 끝까지 못 가게 한 의도.

부적 순서를 생각하고 조합을 노리는 사람이면 이보다 높아야 한다 — 실제 플레이테스트로 확인할 부분.
"위험 고려" 정책이 탐욕보다 낫지 않은 건 감점 공식이 단순해서다. 위험 표시가 사람에게 쓸모 있는지는 플레이로 본다.
